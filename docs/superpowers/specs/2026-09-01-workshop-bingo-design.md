# 사내 워크숍 빙고 웹 — 설계 스펙

날짜: 2026-09-01
상태: 승인됨 (채팅에서 설계 승인)

## 목적

사내 워크숍용 웹 게임 허브. 이번 단계에서는 **빙고 게임**을 완성한다.
(아이스브레이킹은 슬랙 선착순 댓글로 웹 외부에서 진행. 퀴즈는 다음 단계.)

## 요구사항

- 참가자 ~20명, 각자 폰으로 접속해 이름만 입력하고 입장.
- 5x5 빙고판. 관리자가 등록한 항목 25개가 참가자마다 랜덤 배치.
- 참가자는 자기 판의 칸을 자유롭게 칠하고/해제한다 (진행자 호출 없음).
- 대시보드(빔프로젝터용)에서 전원의 칠한 칸 수 + 빙고 줄 수를 실시간 확인.
- 워크숍 일회성 용도. 외부 서비스 의존 없이 `node server.js` 하나로 실행.

## 아키텍처

- **서버**: Node.js + Express 단일 프로세스.
  - 상태는 인메모리, 변경 시 `data.json`에 디바운스 저장(재시작 대비).
  - 실시간: SSE (`GET /api/events`) 로 전체 상태 스냅샷 푸시.
- **프론트**: 바닐라 JS + 정적 HTML/CSS, 빌드 스텝 없음. `public/` 에서 서빙.
- **신원**: 참가자 ID를 localStorage에 저장 → 새로고침해도 자기 판 유지.
- **인증**: 없음 (사내용). `/admin` 은 경로만 아는 사람이 사용.

## 화면

| 경로 | 용도 |
|------|------|
| `/` | 게임 허브 (빙고 링크; 이후 퀴즈 추가 자리) |
| `/bingo` | 참가자 화면: 이름 입력 → 5x5 판, 탭으로 칠하기/해제. 모바일 우선 |
| `/board` | 대시보드: 전원 이름·칠한 칸 수·빙고 줄 수, 빙고 줄 수→칸 수 정렬, 빙고 하이라이트 |
| `/admin` | 항목 25개 입력/수정, 게임 리셋 |

## API

- `POST /api/join` `{name}` → `{participantId, layout, items}` — 새 참가자 등록, 25개 항목 랜덤 순열 배치
- `POST /api/mark` `{participantId, cellIndex, on}` → 칸 토글
- `GET /api/events` — SSE, 연결 시 및 상태 변경 시 전체 스냅샷 push
- `GET /api/state` — 스냅샷 폴백
- `POST /api/admin/items` `{items: string[25]}` — 항목 설정 (설정 시 기존 참가자 판은 유지 정책: 리셋 권장)
- `POST /api/admin/reset` — 참가자 전원 삭제, 새 게임

## 데이터 모델

```js
{
  items: string[25],
  participants: [{
    id: string,          // 랜덤 토큰
    name: string,
    layout: number[25],  // items 인덱스의 순열
    marked: boolean[25]
  }]
}
```

빙고 줄 = 가로 5 + 세로 5 + 대각 2 = 12줄. 줄 수 계산은 서버에서 수행해 스냅샷에 포함.

## 테스트

`node --test`. 대상: 빙고 줄 계산(0줄/가로/세로/대각/다중), join(레이아웃이 유효한 순열인지, 이름 중복 처리), mark 토글, reset, admin items 검증(25개 아니면 거부).

## 비범위 (YAGNI)

- 퀴즈 게임 (다음 단계, 허브에 자리만)
- 로그인/인증, DB, 배포 파이프라인
- 슬랙 연동
